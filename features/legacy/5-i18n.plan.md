# Plan: i18n Support (feature 5-i18n)

## Context
Kino currently has all UI text hardcoded in English. This feature adds multilingual support using next-intl, with locale detection from the browser's Accept-Language header on first visit, and a manual override saved to a cookie and the user's DB profile. Supported languages: English (en), Spanish (es), Portuguese (pt), German (de).

Locale routing is fully cookie-based — no URL prefix changes. The locale cookie is read on every request to resolve the right message file. This is a pragmatic first approach that keeps the URL structure unchanged.

---

## Architecture

```
browser Accept-Language
       ↓
middleware.ts  →  sets 'locale' cookie on first visit
       ↓
i18n/request.ts  →  reads 'locale' cookie, loads messages/[locale].json
       ↓
NextIntlClientProvider  →  provides translations to client components
       ↓
server: getTranslations() / client: useTranslations()
```

## Backend Changes

### 1. Migration
**New file:** `backend/migrations/add_locale_to_users.sql`
```sql
ALTER TABLE users ADD COLUMN IF NOT EXISTS locale VARCHAR(10) NOT NULL DEFAULT 'en';
```
Apply manually: `docker exec -it kino-postgres psql -U postgres -d kino -f /path/to/migration`

### 2. Schema — `backend/app/schemas/user.py`
- Add `locale: str = 'en'` to `UserResponse`
- Add `locale: str | None = None` to `UserUpdate`

### 3. CRUD — `backend/app/crud/users.py`
Add `update_user(db, user_id, updates: dict) -> dict | None`:
- Builds dynamic SET clause from provided fields
- Appends `updated_at = NOW()`
- Returns updated row

### 4. Router — `backend/app/routers/users.py`
Add `PATCH /api/users/{user_id}` endpoint:
- Auth required: only the user themselves can update (`current_user["id"] == user_id`)
- Delegates to `crud.update_user()`
- Returns `UserResponse`

### 5. Integration Tests — `backend/tests/integration/test_users.py`
- `test_user_can_update_locale` → PATCH with `{"locale": "es"}`, assert 200 + locale persisted
- `test_user_cannot_update_other_users_locale` → PATCH another user's ID, assert 403
- `test_locale_defaults_to_en` → GET user, assert `locale == "en"`

## Frontend Changes

### 6. Install next-intl
```bash
npm install next-intl
```

### 7. Locale config — `frontend/i18n/routing.ts` (new)
```ts
export const locales = ['en', 'es', 'pt', 'de'] as const;
export type Locale = (typeof locales)[number];
export const defaultLocale: Locale = 'en';
```

### 8. Request config — `frontend/i18n/request.ts` (new)
Reads `locale` cookie. Falls back to `defaultLocale`. Loads corresponding `messages/[locale].json`.

### 9. Locale detection utility — `frontend/lib/locale.ts` (new)
`detectLocale(acceptLanguage: string): Locale` — parses Accept-Language header, returns best match from supported locales, or defaultLocale.

### 10. Unit test — `frontend/lib/locale.test.ts` (new)
Tests for `detectLocale`:
- `should return 'es' for Accept-Language: es-ES,es;q=0.9`
- `should return 'en' for Accept-Language: en-US`
- `should return 'de' for Accept-Language: de-DE`
- `should return 'pt' for Accept-Language: pt-BR`
- `should return default locale for unsupported language`
- `should return default locale for empty string`

### 11. Middleware — `frontend/middleware.ts` (new)
On every request: if no `locale` cookie exists, call `detectLocale()` on the Accept-Language header and set the cookie.
```ts
export const config = { matcher: ['/((?!_next|favicon.ico).*)'] };
```

### 12. next.config.ts — modified
Wrap config with `createNextIntlPlugin()`.

### 13. Translation files — `frontend/messages/` (new directory)
Four files: `en.json`, `es.json`, `pt.json`, `de.json`

Namespaces:
- `nav` — Home, My Calendars, Create Calendar, Events, Settings
- `topBar` — Feedback, Profile, Settings, About, Log out, Toggle theme, Change language
- `marketing` — Go to app, Sign in, Get started, landing page text
- `auth` — Login/signup form labels, validation messages, error messages
- `settings` — all Settings page text including Appearance options and Language section
- `deletedCalendars` — page title, subtitle, empty state, Deleted {date}, Restore
- `home`, `calendars`, `events`, `feedback` — page-specific strings
- `common` — Save, Cancel, Delete, Restore, Loading

### 14. Root layout — `frontend/app/layout.tsx` — modified
- Becomes async server component
- Reads `locale` cookie
- Sets `<html lang={locale}>`
- Wraps children with `NextIntlClientProvider`

### 16. Locale server action — `frontend/app/(app)/settings/actions.ts` (new)
`updateLocale(locale: Locale)` server action:
1. Validates locale is in supported list
2. Sets `locale` cookie (non-httpOnly, sameSite: lax)
3. Calls `PATCH /api/users/{userId}` on backend (if logged in)
4. Calls `revalidatePath('/')` to reload translations

### 17. Settings page — `frontend/app/(app)/settings/page.tsx` — modified
Add Language section between Appearance and Calendars:
- Button group for en / es / pt / de (same style as theme buttons)
- Active locale highlighted
- On click: calls `updateLocale()` server action
- Add `data-testid='language-selector'` to the section

### 18. Top bar — `frontend/components/top-bar.tsx` — modified
- Add globe icon button (dev only: `process.env.NODE_ENV === 'development'`)
- Opens dropdown with language options
- On select: calls `updateLocale()` action
- Translate existing text (Profile, Settings, About, Log out, aria-labels)

### 19. Navigation — `frontend/lib/nav.ts` — modified
Change `label` field to a translation key (e.g. `'home'` instead of `'Home'` — translated in the component). Add a `testId` field per item for e2e.

### 20. Desktop sidebar + mobile nav — modified
- Use `useTranslations('nav')` to render labels from keys
- Add `data-testid='nav-home'` (and similar) to nav items using the `testId` field

### 21. All pages with hardcoded text — modified
Apply `getTranslations()` (server components) or `useTranslations()` (client components) in:
- `app/(marketing)/layout.tsx`
- `app/(marketing)/page.tsx`
- `app/(app)/home/page.tsx`
- `app/(app)/calendars/page.tsx`
- `app/(app)/calendars/[uuid]/page.tsx`
- `app/(app)/calendars/[uuid]/edit/page.tsx`
- `app/(app)/events/page.tsx`
- `app/(app)/feedback/page.tsx`
- `app/(app)/settings/page.tsx`
- `app/(app)/settings/deleted-calendars/page.tsx` — also replace hardcoded `'en-US'` in `toLocaleDateString` with dynamic locale
- `app/(marketing)/login/page.tsx`
- `app/(marketing)/signup/page.tsx`
- `app/(marketing)/forgot-password/page.tsx`
- `app/(marketing)/reset-password/page.tsx`
- All components with visible text strings

### 22. E2E test — `frontend/e2e/7-i18n.spec.ts` (new)
```
@i18n.1 should switch language and persist the preference
```
- Navigate to settings
- Click 'es' language button (`data-testid='language-selector'`)
- Verify `data-testid='nav-home'` text becomes 'Inicio'
- Reload page
- Verify 'Inicio' still shown (cookie persisted)
