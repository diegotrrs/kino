# 1. Description

This feature will add i18n support to the app. The user's locale will be detected and stored in a cookie, they can change it in settings.
The supported languages will be: English, Spanish, Portuguese and German. As part of this feature, the existing texts in the app should be translated to those languages.

# 2. Technical specification

## 2.1 Front end

### Library

next-intl will be used as the i18n library. Translations will be saved in JSON files as recommended by. next-intl

### Locale routing

The URLs will stay the same. The locale will be saved in a cookie. This is not ideal for SEO, but it's good enough for a first approach

### Locale Detection

Accept-Language header — the browser sends this automatically with every request. It reflects the user's browser language setting

### Language selection

The user will be able to change their language settings

- Top bar dropdown a globe icon in the top bar that opens a language picker. ONLY displayable in development.
- Add a Language selector in Setting. Saves to the user's profile in the DB.

## 2.2 Backend

The user's locale will be saved in the DB.

# 3. Other

Include unit tests for the front end. Only include one e2e the language switcher itself. For example:

```
 test('@i18n.1 should switch language and persist the preference', async ({ page }) => {
    // switch to Spanish
    await page.getByTestId('language-selector').selectOption('es')

    // verify one landmark string changed — proves the switch worked
    await expect(page.getByTestId('nav-home')).toHaveText('Inicio')

    // reload and verify it persisted
    await page.reload()
    await expect(page.getByTestId('nav-home')).toHaveText('Inicio')
  })
```
